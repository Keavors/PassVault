PassVault 3.1 — офлайн-хранилище и генератор паролей
====================================================

Два приложения — для ПК и для Android — с одним и тем же зашифрованным файлом
vault.pmv. Синхронизация: перенести файл и слить с разбором расхождений на
любой из сторон.

Ниже — что и почему сделано, потому что почти каждое решение здесь чинит
конкретную беду прежних версий.


0. ЧТО ИЗМЕНИЛОСЬ В ВЕРСИИ 3.1
------------------------------
Удаление программы больше не может стереть хранилище
    Самое дорогое из найденного. Удаление выполняло

        rmdir /s /q "папка программы"

    в расчёте на то, что данные лежат где-то отдельно. Но переносимый режим
    кладёт vault.pmv ровно рядом с exe, а установщик по умолчанию предлагает
    тот диск, с которого запущен, — то есть штатный сценарий сам сводит
    программу и данные в одну папку. Кнопка «Удалить» в «Параметрах» стирала
    хранилище, откат и весь архив снимков, а окно удаления в этот момент
    показывало надпись «Хранилище и резервные копии останутся».

    Теперь удаляются поимённо файлы программы, а папка сносится командой
    rmdir БЕЗ ключа /s — она физически не способна удалить непустой каталог.
    Окно удаления показывает, что именно найдено рядом и что останется.

    Тест на это раньше был, но был фальшивым: он сравнивал русскую фразу
    «рядом с файлом хранилища» с путём установки и проходил всегда.

Одно шифрование вместо выбора между сильным и слабым
    Кнопки «Формат шифрования» больше нет. PBKDF2 считается процессором и
    почти не требует памяти, поэтому видеокарта перебирает его тысячами
    попыток параллельно. Argon2id требует 256 МиБ на КАЖДУЮ попытку, и
    преимущество видеокарты исчезает. Держать рядом заведомо более слабый
    вариант — значит предлагать пользователю выбрать похуже.

    Программа ПИШЕТ только PMVAULT2 (Argon2id). PMVAULT1 (PBKDF2) она ЧИТАЕТ
    и будет читать всегда: иначе все существующие хранилища, откаты и снимки
    в архивах стали бы нечитаемыми. Старый файл при первом открытии сам
    переезжает на Argon2id, сняв перед этим копию в архив в прежнем формате.
    Мастер-пароль при этом не меняется, делать ничего не нужно.

Красная надпись про Android убрана — она была неправдой
    Окно «Формат шифрования» три версии подряд сообщало красным текстом:
    «Android-версия PMVAULT2 не открывает». Телефон открывает оба формата:
    Argon2id там считается чистой Java (BouncyCastle). Надпись осталась от
    версии 2.0, где так и было. Тесты совместимости с обеих сторон это
    подтверждают.

Пароль больше не остаётся в буфере обмена навсегда
    Скопированный пароль стирается через 30 секунд (настраивается, 0 —
    выключить). Перед стиранием программа проверяет, что в буфере всё ещё её
    пароль: за эти секунды человек мог скопировать что-то своё.
    Историю буфера Windows (Win+V) программа очистить не может и не обещает.

Архив копий больше не пустует до первой правки
    Снимок делается только при изменении содержимого, поэтому на свежей
    установке архив оставался пустым, пока человек что-нибудь не отредактирует:
    из всех резервных копий существовал только vault.pmv.prev — шаг назад на
    одно сохранение. Теперь первый снимок делается сразу при открытии.

Программа снова запускается из исходников
    `python passvault.py` открывал окно УСТАНОВЩИКА вместо хранилища: проверка
    «называюсь ли я setup» смотрела на имя файла модуля pvault\setup.py и
    находила там слово «setup». Из исходников программа не работала вовсе.

Дубликаты id при слиянии
    Две записи с одинаковым id внутри чужого файла добавлялись обе. Дальше они
    затеняли друг друга при каждой синхронизации: правка на втором устройстве
    не доезжала никогда, и понять почему было невозможно. Теперь такие записи
    разводятся по разным id.

Ничего на системном диске
    Установщик предупреждает, если выбран системный диск, и по умолчанию
    предлагает самый просторный несистемный. Ярлык в меню «Пуск» стал
    необязательным. Самопроверка пишет свои временные файлы рядом с
    программой, а не в профиль пользователя. Автотесты — тоже: раньше они
    создавали десятки временных хранилищ в %TEMP% и вдобавок затирали рабочий
    config.json путями к ним.

Мелочи, которые раздражали
    Список переупорядочивается сразу при переименовании записи, а не при
    следующем обновлении. Обратный отсчёт после неверных паролей больше не
    удваивается при каждой новой попытке. Файл-счётчик vault.pmv.att не
    создаётся, если ни одной ошибки не было. Предел длины пароля везде один
    и тот же (512), а не 256 в одном месте и 512 в другом.


ЧТО ИЗМЕНИЛОСЬ В ВЕРСИИ 3.0
---------------------------
Программа больше не теряет хранилище из виду
    Прежняя версия искала vault.pmv ровно в одной папке — рядом с exe. Если
    программа лежала в подпапке, а файл уровнем выше, она объявляла «хранилище
    ещё не создано», хотя данные были в двух шагах. Теперь проверяются: путь из
    аргумента командной строки, последнее открытое хранилище, папка рядом с
    программой, папка уровнем выше, «Документы» и рабочий стол. Плюс список
    недавних хранилищ на экране входа.

Ничего на системном диске
    Прежняя сборка складывала предыдущую версию, снимки и настройки в
    %APPDATA%. Теперь всё лежит рядом с самим хранилищем, папку архива можно
    указать любую, а в профиль пользователя программа не пишет вообще ничего.

Android открывает PMVAULT2
    Argon2id на телефоне считается чистой Java (BouncyCastle), нативная
    библиотека не нужна. Формат больше не разделяет устройства.

Пароль больше не пропадает при слиянии
    Выбор «взять из файла» затирал локальный пароль без следа — при том что
    история паролей существует ровно для таких случаев. Теперь при замене
    локальный пароль уходит в историю, а истории обеих сторон объединяются.

Снимок «перед слиянием» снимает то, что на экране
    Версия 2.0 считала отпечаток по данным в памяти, а файл копировала с
    диска. Эти двое расходились: обещание «откатимся, если что» могло
    относиться к другому состоянию, а ближайшее штатное сохранение решало, что
    менять нечего, и снимок пропускало. Теперь снимок пишется теми же байтами,
    что легли в vault.pmv, а несохранённые правки перед событийным снимком
    сохраняются.

Задержка после неверных паролей
    Три попытки — пауза, дальше пауза растёт: 5 с, 30 с, 2 мин, 10 мин, 30 мин.
    Состояние на диске, перезапуск программы паузу не снимает.

Установщик и приложение — один файл
    Раньше рядом с программой лежал ещё и uninstall.exe на 28 МБ. Теперь всё в
    одном exe: 15 МБ вместо 45.

Что перешло из 2.0 и осталось
    Атомарная запись с проверкой расшифровкой, архив снимков с ротацией,
    корзина, история паролей, слияние с разбором конфликтов, экспорт и импорт
    CSV/JSON, файл-замок против двух копий программы, экран восстановления
    вместо «создай новое».

Совместимость
    Формат PMVAULT1 не менялся. Хранилища от 1.x, 2.0 и с телефона
    открываются как есть, без конвертации.


1. УСТАНОВКА
------------
Готовый установщик
    Запусти PassVault-Setup-3.0.exe. Python и библиотеки на целевом
    компьютере не нужны — всё внутри. Права администратора не требуются.
    По умолчанию ставится на тот же диск, с которого запущен установщик;
    путь можно поменять в окне установки.
    Удаление — «Параметры → Приложения».

Без установки
    Положи PassVault.exe куда угодно и запусти. Установщик и приложение — один
    и тот же файл, различаются именем: PassVault-Setup-*.exe ставит,
    PassVault.exe открывает хранилище.

Из исходников
    1) Python 3.10+ с python.org (галочка «Add Python to PATH»)
    2) pip install cryptography
       pip install argon2-cffi        (обязательно: это единственный KDF)
    3) python passvault.py

Самопроверка:
    python passvault.py --test         автотесты
    PassVault.exe --selfcheck          проверка собранного exe

Удаление
    «Параметры → Приложения → PassVault». Хранилище, откат и архив снимков
    НЕ удаляются, даже если лежат в одной папке с программой: удаляются
    поимённо файлы программы, а папка сносится только если в ней ничего
    больше не осталось.


2. СБОРКА
---------
    python build.py

Скрипт доустановит недостающее, нарисует иконку, прогонит автотесты и соберёт
в dist\:

    PassVault-Setup-3.0.exe    установщик — его и носи на другие ПК
    PassVault.exe              то же самое под именем приложения

Если автотесты не проходят, сборка останавливается: собирать менеджер паролей
с падающими тестами нельзя.

Ключи: --skip-tests, --clean, --console

UPX намеренно отключён: сжатый неподписанный exe регулярно ловит ложные
срабатывания антивирусов.


3. ГДЕ ЛЕЖАТ ДАННЫЕ
-------------------
Всё рядом с хранилищем:

    vault.pmv                 хранилище
    vault.pmv.prev            предыдущая версия для отката
    vault.pmv.lock            признак «открыто», снимается при выходе
    vault.pmv.att             счётчик неверных паролей
    vault_backups\            архив снимков

Папку архива можно перенести куда угодно: Инструменты -> Настройки.

Список последних открытых файлов лежит рядом с программой, в config.json.
В профиль пользователя (%APPDATA%) программа не пишет НИЧЕГО. Если рядом с
программой писать нельзя, список последних файлов просто не сохраняется.

Служебные файлы прежних версий (.bak, .tmp, папка vault_backups рядом с
файлом, а также то, что предыдущая сборка успела положить в %APPDATA%) при
первом открытии переезжают к хранилищу. Ничего не выбрасывается: даже
недописанный .tmp сохраняется в архив снимков — именно он может оказаться
последней уцелевшей копией.


4. КАК УСТРОЕНА ЗАЩИТА
----------------------
 - Мастер-пароль → Argon2id (3 прохода, 256 МиБ памяти, 4 потока), случайная
   соль 16 байт → ключ AES-256. 256 МиБ на КАЖДУЮ попытку — это и есть то,
   что обесценивает перебор на видеокартах: карта с 24 ГБ памяти удержит
   меньше сотни попыток параллельно вместо тысяч.
   Выбора больше нет: PBKDF2 читается ради старых файлов, но не пишется.
 - Файл шифруется AES-256-GCM. GCM заодно проверяет целостность: неверный
   пароль, повреждение или подмена файла дают ошибку открытия, а не мусор.
 - Каждое число из заголовка файла проверяется на разумность. Без этого
   подсунутый файл с максимальным uint32 в поле итераций замораживал
   программу на минуты без возможности отмены.
 - Генерация паролей — криптографический ГСЧ ОС (SystemRandom), включая
   перемешивание. Генерировать стойко и перемешивать обычным random —
   классическая ошибка, сводящая стойкость на нет.
 - Оценка стойкости намеренно занижена: символы из «обязательно включить»
   заданы тобой и предсказуемы, поэтому в зачёт не идут.
 - Три неверных пароля — пауза, дальше пауза растёт.
 - Автоблокировка при бездействии настраивается.
 - Скопированный пароль стирается из буфера обмена через 30 секунд
   (Инструменты → Настройки; 0 — не стирать). Перед стиранием программа
   проверяет, что в буфере всё ещё её пароль, — стирать чужое нельзя.
 - Удалённые записи остаются «надгробиями» — так удаление переносится при
   слиянии. Старше 180 дней их можно вычистить вручную.

Честно о пределах:
 - без мастер-пароля файл — случайный шум; единственная атака это перебор
   мастер-пароля, а стойкость равна длине и непредсказуемости твоей фразы;
 - пока хранилище открыто, данные лежат в оперативной памяти;
 - из буфера обмена пароль стирается по таймеру, НО в историю буфера Windows
   (Win+V) он попадает в момент копирования, и оттуда программа его убрать
   не может — там его чистить только руками;
 - задержка после неверных попыток защищает от чужих рук на разблокированном
   компьютере, но не от перебора самого файла: там работает только KDF;
 - от кейлоггера шифрование не спасает.

Про блокировку сети. Внутри программы сетевые функции Python отключены, любая
попытка соединения падает с ошибкой. Это защита в глубину, а не гарантия: код,
работающий с ОС напрямую, её обойдёт. Гарантия уровня системы — правило
брандмауэра (cmd от администратора, путь замени на свой):

  netsh advfirewall firewall add rule name="PassVault out" dir=out program="%LOCALAPPDATA%\Programs\PassVault\PassVault.exe" action=block enable=yes
  netsh advfirewall firewall add rule name="PassVault in"  dir=in  program="%LOCALAPPDATA%\Programs\PassVault\PassVault.exe" action=block enable=yes

На Android жёстче: в манифесте не объявлено разрешение INTERNET — без него
ядро Android физически не даст приложению открыть сокет.


5. КАК НЕ ПОТЕРЯТЬ ДАННЫЕ
-------------------------
Запись на диск
    Новый файл пишется во временный с fsync, тут же проверяется расшифровкой
    (ключ уже в памяти, KDF гонять не нужно — проверка стоит миллисекунду),
    предыдущая версия КОПИРУЕТСЯ в служебную папку, и только потом временный
    файл атомарно занимает место основного. vault.pmv не исчезает с диска ни
    на мгновение.

    В версии 1.x порядок был другой:
        os.replace(vault, vault + ".bak")   # здесь vault.pmv НЕ СУЩЕСТВУЕТ
        os.replace(tmp, vault)
    Сбой между этими строками оставлял систему без vault.pmv, программа
    предлагала «создать хранилище», и первое же автосохранение затирало
    последнюю копию. Две операции от сбоя до полной потери. Теперь на это
    есть тест, который имитирует сбой в каждой точке записи.

Четыре независимых слоя копий, каждый ловит свой вид потери:

Корзина (Правка → Корзина)
    Удалённые записи видны и возвращаются одной кнопкой.

История паролей (кнопка «История…» у поля пароля)
    До 10 прошлых паролей записи. Пополняется при смене пароля, при вставке из
    генератора и при слиянии.

Архив снимков (Копии → Резервные копии)
    Снимок делается при сохранении, но не чаще раза в 5 минут и только если
    содержимое действительно изменилось (сравнивается открытый текст, а не
    шифртекст — он меняется каждый раз из-за нового nonce).
    Плюс один снимок сразу при открытии, если архив пуст: иначе на свежей
    установке резервных копий не существует до первой правки.
    Ротация «дед-отец-сын»:
        последние       12 снимков независимо от возраста
        почасовые       по одному на час за 24 часа
        дневные         по одному на день за 30 дней
        месячные        по одному на месяц за 12 месяцев
        событийные      перед слиянием, сменой пароля, сменой формата,
                        восстановлением, чисткой и импортом — последние 10
    Около 80 файлов, меньше двух мегабайт при типичном размере хранилища.

    Восстановление идёт СЛИЯНИЕМ, а не заменой файла: вернуть запись,
    удалённую вчера, можно не потеряв то, что добавлено сегодня.

    Снимки — обычные файлы .pmv, их можно открыть через «Открыть другой
    файл…». Снимок, сделанный до смены мастер-пароля, зашифрован ПРЕЖНИМ
    паролем — программа спросит его отдельно.

Плюс previous.pmv — предыдущая версия для мгновенного отката.

Если vault.pmv всё-таки пропал, программа показывает список уцелевших копий и
предлагает восстановиться. Предложить «создать новое» в этот момент — прямой
путь к потере, поэтому такой вариант есть, но он не первый.


6. ФОРМАТ ФАЙЛА
---------------
PMVAULT2 (Argon2id) — ЕДИНСТВЕННЫЙ формат записи:
   8  байт   magic = "PMVAULT2"
   1  байт   id алгоритма (2 = Argon2id)
   4  байта  time_cost (uint32 BE)
   4  байта  memory_cost в КиБ (uint32 BE)
   1  байт   parallelism
   16 байт   соль
   12 байт   nonce (GCM)
   далее     шифртекст AES-256-GCM (тег 16 байт в конце)

PMVAULT1 (PBKDF2) — только ЧТЕНИЕ, для файлов версий 1.x и 2.x:
   8  байт   magic = "PMVAULT1"
   4  байта  итерации PBKDF2 (uint32, big-endian)
   16 байт   соль
   12 байт   nonce
   далее     шифртекст AES-256-GCM

Оба формата открываются и на ПК, и на Android — телефон считает Argon2id
чистой Java (BouncyCastle), нативная библиотека ему не нужна.

Переключателя форматов нет. Старый файл при первом открытии переезжает на
PMVAULT2 сам: сначала в архив кладётся снимок «preformat» в ПРЕЖНЕМ формате
(его можно открыть, если перешифровка не доедет), потом хранилище
перешифровывается. Мастер-пароль не меняется.

Чтение PMVAULT1 останется в программе навсегда. Убери его — и каждый
существующий vault.pmv, каждый vault.pmv.prev и каждый снимок в архиве
превратятся в нечитаемый мусор: формат записан в первых восьми байтах файла.

Открытый текст — JSON UTF-8:
   {"version":1,
    "entries":[{id,title,login,password,url,notes,created,modified
                [,deleted][,history]}],
    "settings":{"generator":{...},"app":{...}}}

Метки времени: ISO-8601 в UTC с секундами — "2026-01-31T11:05:42Z".
Прежний формат "2026-01-31 14:05" (местное время, без секунд) по-прежнему
читается. Старый формат ломал сравнение «что новее» между устройствами в
разных часовых поясах и не различал правки внутри одной минуты.

Поля url и history необязательные: файл без них читается нормально.

Незнакомые поля НЕ ВЫБРАСЫВАЮТСЯ. Если файл пришёл из более новой версии и
содержит поле, о котором эта программа не знает, поле уезжает обратно в файл
нетронутым. Иначе каждая синхронизация отгрызала бы по куску данных.


7. СИНХРОНИЗАЦИЯ = НАСТОЯЩЕЕ СЛИЯНИЕ
------------------------------------
ПК → телефон: Файл → «Сохранить копию как…» → файл на телефон →
              в приложении «⋮» → «Импорт и слияние».
Телефон → ПК: «⋮» → «Экспорт копии» → файл на ПК →
              Файл → «Слить с другим файлом…».

Правила слияния одинаковы на обеих сторонах:
 - записи, которых нет, добавляются автоматически;
 - записи с одинаковым содержимым пропускаются молча, даже если даты правки
   различаются;
 - расхождения показываются с обеими версиями целиком и пометкой «новее»;
 - можно взять везде самое свежее одной кнопкой — спросят только про те
   записи, что правились в одну и ту же секунду;
 - есть флажок «применить ко всем оставшимся»;
 - удаления переносятся;
 - при замене записи прежний пароль сохраняется в истории;
 - отмена в любом окне отменяет ВСЁ слияние, файлы не меняются;
 - перед слиянием делается снимок.

Чтобы обе стороны стали одинаковыми: слей на устройстве А, затем экспортируй
результат с А и слей на Б.


8. ПЕРЕНОС В ДРУГОЙ МЕНЕДЖЕР И ОБРАТНО
--------------------------------------
Файл → Экспорт в CSV / в JSON. Файл сохраняется БЕЗ ШИФРОВАНИЯ — после
переноса удали его и очисти корзину системы.

Файл → Импорт из CSV/JSON. Понимает выгрузки Bitwarden и KeePass (заголовки
name/login_username/login_password/login_uri и Account/Login Name/Password/
Web Site), кодировки utf-8, cp1251 и cp866, разделители «,», «;» и табуляцию.
Импорт только добавляет записи, существующие не трогает.


9. ГОРЯЧИЕ КЛАВИШИ
------------------
Ctrl+S — сохранить сейчас (и так сохраняется само через ~1 с после правки)
Ctrl+N — новая запись
Ctrl+L — заблокировать
Ctrl+B — резервные копии
Поиск слева ищет по названию, логину, адресу и заметкам.


10. УСТРОЙСТВО КОДА
-------------------
    passvault.py            точка входа
    build.py                сборка exe и установщика
    pvault/crypto.py        контейнер, KDF, шифрование
    pvault/model.py         записи, метки времени, история, надгробия
    pvault/generator.py     генератор паролей
    pvault/merge.py         слияние
    pvault/paths.py         где лежат хранилище и служебные файлы
    pvault/storage.py       атомарная запись, замок, поиск копий
    pvault/backup.py        архив снимков и ротация
    pvault/portable.py      экспорт/импорт CSV и JSON
    pvault/throttle.py      задержка после неверных паролей
    pvault/config.py        список последних файлов (рядом с программой)
    pvault/session.py       открытое хранилище: сохранение, слияние, пароль
    pvault/setup.py         установка и удаление
    pvault/netblock.py      отключение сети
    pvault/ui/              интерфейс (единственный слой, знающий про tkinter)
    tests/                  автотесты (185 штук)
    tools/make_icon.py      иконка рисуется кодом
    tools/make_android_fixture.py   эталоны для тестов Android-проекта

Автотесты ничего не пишут ни в профиль пользователя, ни на системный диск:
tests/__init__.py уводит tempfile и config.json в .testtmp рядом с проектом.
Раньше они создавали временные хранилища в %TEMP% и вдобавок затирали рабочий
config.json путями к ним — после прогона программа пыталась открыть
несуществующий временный файл.

Граница проведена в одном месте: всё, кроме pvault/ui, не знает про tkinter и
проверяется тестами без единого окна на экране. Это не вкусовщина. В версии
1.x программа лежала одним файлом, слой записи на диск нельзя было зацепить
тестом, и именно там жил баг, стиравший хранилище. Тест, который выдёргивает
питание ровно в опасный момент, можно написать только к отделённому слою.


11. СОВМЕСТИМОСТЬ С ANDROID-ВЕРСИЕЙ
-----------------------------------
Проект телефона: D:\AndroidStudioApps\PassVault (см. README_ANDROID.txt).
Другой путь задаётся переменной PASSVAULT_ANDROID_PROJECT.

Расхождение форматов между устройствами съедает данные молча, поэтому оно
проверяется на настоящих файлах, в обе стороны:

ПК → Android
    python tools\make_android_fixture.py
    кладёт в тесты Android-проекта ДВА эталона: pc_vault_argon2.pmv (PMVAULT2,
    то, что ПК теперь пишет) и pc_vault.pmv (PMVAULT1, то, что ПК обязан
    читать вечно). Там их читает PcCompatibilityTest и проверяет заодно, что
    незнакомые поля переживают перезапись телефоном.

Android → ПК
    Android-тест пишет файл в app\build\interop\android_vault.pmv, а
    tests/test_android_interop.py читает его оттуда. Если Android-тесты не
    запускали, эти проверки просто пропускаются.

Порядок при изменении формата:
    1) правишь формат, python passvault.py --test
    2) python tools\make_android_fixture.py
    3) в Android-проекте: gradlew :app:testDebugUnitTest
    4) снова python passvault.py --test
