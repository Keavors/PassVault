PassVault 2.0 — офлайн-хранилище и генератор паролей
=====================================================

Два приложения (ПК и Android) с одним и тем же зашифрованным форматом файла
vault.pmv. Синхронизация — перенос файла и слияние с разбором конфликтов на
любой из сторон.


0. ЧТО ИЗМЕНИЛОСЬ В ВЕРСИИ 2.0
------------------------------
Главное: починена потеря данных. В прежней версии запись файла шла так —

    os.replace(vault, vault + ".bak")   # здесь vault.pmv НЕ СУЩЕСТВУЕТ
    os.replace(tmp, vault)

Сбой между этими строками оставлял систему без vault.pmv. Программа при
следующем запуске предлагала «создать хранилище», и первое же автосохранение
затирало последнюю уцелевшую копию. Две операции от сбоя до полной потери.

Что сделано:
 - предыдущая версия теперь КОПИРУЕТСЯ, а не переименовывается: vault.pmv не
   исчезает с диска ни на мгновение;
 - записанный файл сразу проверяется расшифровкой — порча ловится, пока
   прежняя версия ещё цела;
 - если vault.pmv всё же пропал, программа показывает список уцелевших копий
   и предлагает восстановиться, а не создать пустое хранилище;
 - вместо одного .bak, отстающего на одно сохранение, появился архив снимков
   с ротацией (см. раздел 5);
 - появилась корзина: удалённые записи можно вернуть;
 - появилась история паролей в записи;
 - ошибки сохранения больше не проглатываются молча (раньше правки могли
   исчезнуть при закрытии программы и при автоблокировке);
 - две запущенные копии программы больше не затирают правки друг друга.

Совместимость: формат PMVAULT1 не менялся. Существующие хранилища с ПК и с
телефона открываются как есть, без конвертации.


1. УСТАНОВКА
------------
Готовый установщик (проще всего)
    Запусти PassVault-Setup-2.0.exe. Python и библиотеки на целевом
    компьютере не нужны — всё уже внутри.
    Программа ставится в %LOCALAPPDATA%\Programs\PassVault под текущего
    пользователя, права администратора не требуются.
    Удаление — «Параметры → Приложения» или uninstall.exe в папке программы.

Из исходников
    1) Python 3.10+ с python.org (галочка "Add Python to PATH")
    2) pip install cryptography
       pip install argon2-cffi      (необязательно — для формата PMVAULT2)
    3) python passvault.py

Самопроверка (крипта, генератор, слияние, запись на диск, интерфейс):
    python passvault.py --test


2. СБОРКА УСТАНОВЩИКА
---------------------
    python build_installer.py

Скрипт сам доустановит недостающее (pyinstaller, cryptography, argon2-cffi),
прогонит автотесты и соберёт в папку dist:

    PassVault.exe                — приложение одним файлом
    PassVault-Setup-2.0.exe      — установщик, его и носи на другие ПК

Если автотесты не проходят, сборка останавливается: собирать менеджер
паролей с падающими тестами нельзя.

Ключи: --skip-tests, --app-only, --clean

UPX намеренно отключён — сжатый неподписанный exe часто ловит ложные
срабатывания антивирусов.


3. ГДЕ ЛЕЖАТ ДАННЫЕ
-------------------
Переносимый режим: если vault.pmv лежит рядом с программой, используется он.
Так продолжают работать уже сложившиеся установки (папка с exe и файлом).

После установки установщиком: %APPDATA%\PassVault\
    vault.pmv                    хранилище
    vault.pmv.prev               предыдущая версия (мгновенный откат)
    vault.pmv.lock               признак «открыто», удаляется при выходе
    vault_backups\               архив снимков

Данные лежат отдельно от программы намеренно: удаление или переустановка
приложения их не трогает.


4. КАК УСТРОЕНА ЗАЩИТА
----------------------
 - Мастер-пароль -> PBKDF2-HMAC-SHA256, 600 000 итераций, случайная соль
   16 байт -> ключ AES-256. Необязательно: Argon2id (Инструменты -> Усилить
   шифрование). Argon2id требует много памяти на попытку, поэтому видеокарты
   теряют преимущество при переборе.
 - Файл шифруется AES-256-GCM; GCM заодно проверяет целостность: неверный
   пароль, повреждение или подмена файла = ошибка открытия.
 - Параметры из заголовка файла проверяются на разумность. Раньше подсунутый
   файл с максимальным значением итераций замораживал интерфейс на ~10 минут.
 - Генерация паролей — криптографический ГСЧ ОС (SystemRandom), включая
   перемешивание.
 - Автоблокировка и очистка буфера обмена настраиваются (Инструменты ->
   Настройки).
 - Удалённые записи остаются «надгробиями» (deleted: true) — так удаление
   переносится при слиянии. Старше 180 дней их можно вычистить вручную.

Честно о пределах:
 - без мастер-пароля файл — случайный шум; единственная атака — перебор
   мастер-пароля, стойкость = длина и непредсказуемость твоей фразы;
 - пока хранилище открыто, данные есть в оперативной памяти;
 - ИСТОРИЯ БУФЕРА ОБМЕНА WINDOWS (Win+V) и её облачная синхронизация
   сохраняют скопированный пароль независимо от автоочистки в программе.
   Если это важно — отключи историю буфера в параметрах системы;
 - от кейлоггера или чужих рук на разблокированном ПК шифрование не спасает.

Про блокировку сети. Внутри программы сетевые функции Python отключены, любая
попытка соединения падает с ошибкой. Это защита в глубину, а не гарантия:
код, работающий с ОС напрямую, её обойдёт. Гарантия уровня системы — правило
брандмауэра (cmd от администратора, путь замени на свой):

  netsh advfirewall firewall add rule name="PassVault out" dir=out program="%LOCALAPPDATA%\Programs\PassVault\PassVault.exe" action=block enable=yes
  netsh advfirewall firewall add rule name="PassVault in"  dir=in  program="%LOCALAPPDATA%\Programs\PassVault\PassVault.exe" action=block enable=yes

На Android жёстче: в манифесте не объявлено разрешение INTERNET — без него
ядро Android физически не даст приложению открыть сокет.


5. РЕЗЕРВНЫЕ КОПИИ
------------------
Три независимых слоя, каждый ловит свой вид потери.

Корзина (Правка -> Корзина)
    Удалённые записи видны и возвращаются одной кнопкой.

История паролей (кнопка «История…» у поля пароля)
    Прежние пароли записи, до 10 штук. Пополняется при смене пароля и при
    вставке из генератора.

Архив снимков (Копии -> Резервные копии)
    Снимок делается при сохранении, но не чаще раза в 5 минут и только если
    содержимое действительно изменилось (сравнивается открытый текст, а не
    шифртекст — он меняется каждый раз из-за нового nonce).
    Ротация «дед-отец-сын»:
        последние       12 снимков независимо от возраста
        почасовые       по одному на час за 24 часа
        дневные         по одному на день за 30 дней
        месячные        по одному на месяц за 12 месяцев
        событийные      перед слиянием, сменой пароля, восстановлением и
                        чисткой — последние 10
    Около 80 файлов, меньше двух мегабайт при типичном размере хранилища.

    Восстановление идёт СЛИЯНИЕМ, а не заменой файла: вернуть запись,
    удалённую вчера, можно не потеряв то, что добавлено сегодня.

    Снимки — обычные файлы .pmv, их можно открыть через «Открыть другой
    файл…». Снимки, сделанные до смены мастер-пароля, зашифрованы ПРЕЖНИМ
    паролем — программа спросит его отдельно.

Плюс vault.pmv.prev — предыдущая версия для мгновенного отката.


6. ФОРМАТ ФАЙЛА
---------------
PMVAULT1 (по умолчанию, читается Android-версией):
   8  байт   magic = "PMVAULT1"
   4  байта  итерации PBKDF2 (uint32, big-endian)
   16 байт   соль
   12 байт   nonce (GCM)
   далее     шифртекст AES-256-GCM (тег 16 байт в конце)

PMVAULT2 (необязательный, Argon2id):
   8  байт   magic = "PMVAULT2"
   1  байт   id алгоритма (2 = Argon2id)
   4  байта  time_cost (uint32 BE)
   4  байта  memory_cost в КиБ (uint32 BE)
   1  байт   parallelism
   16 байт   соль
   12 байт   nonce
   далее     шифртекст AES-256-GCM

ВНИМАНИЕ: PMVAULT2 Android-версия не откроет, пока не будет обновлена.

Открытый текст — JSON UTF-8:
   {"version":1,
    "entries":[{id,title,login,password,url,notes,created,modified
                [,deleted][,history]}],
    "settings":{"generator":{...},"app":{...}}}

Метки времени: ISO-8601 в UTC с секундами — "2026-01-31T11:05:42Z".
Прежний формат "2026-01-31 14:05" (местное время, без секунд) по-прежнему
читается. Старый формат ломал сравнение «что новее» между устройствами в
разных часовых поясах и не различал правки внутри одной минуты.

Поля url и history необязательные: файл без них читается нормально.


7. СИНХРОНИЗАЦИЯ = НАСТОЯЩЕЕ СЛИЯНИЕ
------------------------------------
ПК -> телефон: Файл -> «Сохранить копию как…» -> файл на телефон ->
               в приложении «⋮» -> «Импорт и слияние».
Телефон -> ПК: «⋮» -> «Экспорт копии» -> файл на ПК ->
               Файл -> «Слить с другим файлом…».

Правила слияния одинаковы на обеих сторонах:
 - записи, которых нет, добавляются автоматически;
 - записи с одинаковым содержимым пропускаются молча;
 - расхождения показываются с обеими версиями целиком и пометкой «новее»;
 - можно взять везде самое свежее одной кнопкой, а спросят только про те
   записи, что правились в одну и ту же секунду;
 - есть флажок «применить ко всем оставшимся»;
 - удаления переносятся;
 - отмена в любом окне отменяет ВСЁ слияние, файлы не меняются;
 - перед слиянием автоматически делается снимок.

Чтобы обе стороны стали одинаковыми: слей на устройстве А, затем экспортируй
результат с А и слей на Б.


8. ПЕРЕНОС В ДРУГОЙ МЕНЕДЖЕР И ОБРАТНО
--------------------------------------
Файл -> Экспорт в CSV / в JSON. Файл сохраняется БЕЗ ШИФРОВАНИЯ — после
переноса удали его и очисти корзину системы.

Файл -> Импорт из CSV/JSON. Понимает выгрузки Bitwarden и KeePass
(заголовки name/login_username/login_password/login_uri и
Account/Login Name/Password/Web Site). Импорт только добавляет записи,
существующие не трогает.


9. ГОРЯЧИЕ КЛАВИШИ
------------------
Ctrl+S — сохранить сейчас (и так сохраняется само через ~1 с после правки)
Ctrl+N — новая запись
Ctrl+L — заблокировать
Ctrl+B — резервные копии
Поиск слева ищет по названию, логину, адресу и заметкам.


10. УСТРОЙСТВО КОДА
-------------------
    passvault.py          точка входа
    tools/                вспомогательные скрипты
    pvault/crypto.py      контейнер, KDF, шифрование
    pvault/model.py       записи, метки времени, история, надгробия
    pvault/merge.py       слияние
    pvault/generator.py   генератор паролей
    pvault/storage.py     атомарная запись, блокировка, поиск копий
    pvault/backup.py      архив снимков и ротация
    pvault/portable.py    экспорт/импорт CSV и JSON
    pvault/netblock.py    отключение сети
    pvault/ui/            интерфейс
    tests/                автотесты
    installer/            установщик
    build_installer.py    сборка

Разделение сделано ради тестируемости: раньше слой записи на диск не
проверялся ничем, и именно там жил баг с потерей данных. Теперь на него есть
тест, который имитирует сбой ровно в опасный момент и убеждается, что
хранилище остаётся на месте.


11. СОВМЕСТИМОСТЬ С ANDROID-ВЕРСИЕЙ
-----------------------------------
Проект телефона: D:\AndroidStudioApps\PassVault (см. README_ANDROID.txt).

Расхождение форматов между устройствами съедает данные молча, поэтому оно
проверяется на настоящих файлах, в обе стороны:

ПК -> Android
    python tools\make_android_fixture.py
    кладёт эталонный vault.pmv в тесты Android-проекта; там его читает
    PcCompatibilityTest и проверяет, что незнакомые поля переживают
    перезапись телефоном.

Android -> ПК
    Android-тест записывает файл в app\build\interop\android_vault.pmv,
    а tests/test_android_interop.py читает его отсюда. Если Android-тесты не
    запускали, эти проверки просто пропускаются.

Порядок при изменении формата:
    1) правишь формат, python passvault.py --test
    2) python tools\make_android_fixture.py
    3) в Android-проекте: gradlew :app:testDebugUnitTest
    4) снова python passvault.py --test

ВАЖНО: «Инструменты → Усилить шифрование (Argon2id)» переводит файл в формат
PMVAULT2, который Android-версия НЕ открывает. Пока пользуешься телефоном, не
включай его. По умолчанию пишется PMVAULT1.
